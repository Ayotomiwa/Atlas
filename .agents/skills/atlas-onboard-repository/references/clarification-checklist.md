# Repository onboarding clarification checklist

Ask one consolidated round about only material gaps: logical/physical boundary, boundary evidence/type, Git-relative `repository_root`, enclosing repository, included/excluded paths, primary domain, independently addressable components, authoritative external infra/shared/operational context, known upstream/downstream systems, flow boundary, and necessary inaccessible references. Separate operational/product owners, review/approval routes and subject-matter experts; CODEOWNERS alone proves only review routing.

Ask again only when safe staging is blocked. Optional gaps stay possible or not covered.
