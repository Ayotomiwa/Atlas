# atlas-diagram

Read the shared diagram-writing, answer-provenance, persistence, and curation-safety contracts.

Identify one engineering question and the output surface. In a console, prefer a plain-text route, tree, or compact table; use Mermaid only when explicitly requested or reliably rendered. Classify the target as an answer-time view, generated flow diagram, or curator-authored component diagram, then read the owning page/contracts and the smallest evidence set supporting every node and edge.

Apply the shared node-count, evidence, accessibility, uncertainty, and fallback rules. For generated flows, never hand-edit a generated Mermaid block: update evidenced structured steps or the diagram flag only in an approved curation scope, then rebuild. Preserve every fact, confidence, direction, and boundary in a manual component diagram; new semantic connections require staging and curation.

Check Mermaid syntax with an available renderer when practical and inspect readability separately. Do not install rendering dependencies without approval. Reuse an owning workflow's scope-bound approval, or preview and route persisted work through that workflow.

Report the question answered, evidence, chosen diagram or fallback, syntax and readability checks, protected generated content, and unresolved gaps. Never treat visual adjacency as causality.
