# Human intent contract

Present Atlas through four ordinary actions; skill names, buckets, lifecycle codes and helper commands are implementation details unless audit detail is requested.

- **Ask Atlas:** answer engineering and impact questions. Use linked pages as the navigation core, deterministic search as an identity entrance, indexes as fallback, maps after ID selection for reverse/multi-hop routes, and bounded source fallback when coverage ends.
- **Teach Atlas:** save a reusable fact or answer an open question. Resolve provenance, duplicates, target and staging bucket internally, then use one concrete preview and scope-bound approval.
- **Sync Atlas:** establish a full repository baseline, discover standards or process merged default-branch changes. Assess all required onboarding lenses; unknown/inaccessible/not-applicable is valid, unsupported records are not.
- **Curate Atlas:** reconcile eligible evidence in the current repository/domain/ID/topic scope and include independent semantic review inside the normal workflow.

State an ambiguous write interpretation before acting. Never require users to choose a skill or internal code. Preserve provenance, uncertainty, explicit persistence approval, independent review and human-controlled publication. Show plain-language outcomes before audit detail. Missing coverage is never evidence of absence.
