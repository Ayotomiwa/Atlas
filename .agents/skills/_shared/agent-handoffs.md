# Specialist-agent handoffs

The parent owns eligibility, routing, selected IDs, source scope, approvals and final presentation. An analyst uses the supplied records, supplied source state—immutable when the owning workflow requires it—and authorised boundary; it does not restart discovery or widen scope. A small direct lookup may stay with the parent only for one selected record with no ambiguity, traversal, source fallback, impact analysis or history.

Supply objective/output; when source or risk analysis applies, the selected method (`source-analysis`, `change-risk-analysis` or both) and its exact question; absolute roots/current path; typed find/path-context candidates or exact IDs including `not-verified` state; and reusable session state: selected IDs, opened curated pages, requested revision or range, resolved full commit or range, inspected source paths and their revisions, coverage endpoint, route class and checkout-advisory disclosure. For source analysis include the target, claims needing proof and stop condition; include entrypoint candidates only when already known and keep them provisional. For change risk include the exact change/failure boundary; include the delta, safety facts and downstream boundaries only when already known and keep them provisional. Also supply scan boundary/exclusions, fallback limits, user-confirmed facts, unresolved ambiguity and validation deferrals.

Carry the **ephemeral Atlas session** across a handoff. **Reuse** still-valid retained context, selected IDs and opened pages only when repository, revision, question type and required confidence remain compatible. Batch independent Atlas reads of selected records and batch Atlas-located source verification only inside the selected boundary. The analyst uses the selected records and range rather than re-resolving them. **Re-enter** routing through the parent only when the handoff is incomplete, source state changed, or work crosses its authorised boundary or coverage endpoint. Never restart the whole route by default. Full ordered access events belong only in routing evaluation artifacts.

Require findings plus a claim ledger containing claim, source classification, references, confidence/lifecycle, direct/inferred state and inference premises. Also require material route hops, consulted paths, relevant checked-but-not-found paths and coverage/conflicts/questions. When selected, require the complete result defined by `source-analysis.md` or `change-risk-analysis.md`.

The parent skill verifies the cited evidence and method result rather than the summary alone. A cleared concern requires the path or executable evidence that cleared it. The parent preserves the analyst's presentation, adds no unsupported synthesis and exposes file hops at the adaptive depth required. Keep the complete ledger internal unless requested or required for an audit artifact.

Write-capable specialist handoffs carry the exact persistence preview, approval, permitted file/claim/status effects, required contract reads and exact Git path scope. A staging handoff additionally carries one ephemeral duplicate snapshot: searched staging statuses/buckets, curated types/indexes, relevant file-content fingerprints, qualified question IDs, duplicate records, candidate targets and unresolved ambiguity. Refresh the whole snapshot when any searched surface changed; otherwise recheck exact output-path and selected-target identity immediately before writing. Never persist this snapshot. A curator only returns materialized pages and its claim ledger; the parent owns local commits, validation, generation, repair, review and lifecycle. The specialist never expands scope or repeats approval; material changes return for a revised preview.
