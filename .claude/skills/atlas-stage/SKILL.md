# atlas-stage

Read `../_shared/human-intents.md`, `../_shared/persistence-approval.md`, `../_shared/runtime.md`, `../_shared/answer-provenance.md`, `../_shared/curation-safety.md`, `../_shared/clear-writing.md`, `_staging/README.md`, then the selected bucket README/template/index. This is the persistence step behind **Teach Atlas**. Do not use a subagent.

1. Determine whether this is a direct request or an approved internal handoff. A direct request needs the shared concrete staging preview and explicit scope-bound approval. A handoff reuses approval only when its exact claims, files and targets still match. Re-preview a material scope change instead of asking twice for an unchanged one.
2. Build or verify the ephemeral duplicate snapshot defined by the shared handoff contract. Use the full staging, typed curated `find`, exact-route and relevant-index search when the request is direct, the snapshot is incomplete or a searched surface changed. Otherwise recheck only output-path uniqueness, exact qualified-question references, known duplicates and selected-target identity. Never persist the snapshot or silently resolve an ambiguous candidate.
3. Complete the applicable taxonomy, compiler contract and destination-contract reads, then perform the shared branch/HEAD/content-clean recheck. If those checks or duplicate discovery materially change the proposed claims, files, targets, evidence boundary, destructive effects or checkpoint range, return a revised preview. Choose the bucket by the primary reusable fact; split only independent semantic boundaries. Route broad investigation to `atlas-onboard-repository` and incremental merged-default-branch ranges to `atlas-stage-changes`.
4. Allocate a deterministic `STG-YYYYMMDD-<slug>` ID. Draft once using the shared clear-writing contract. Capture one coherent, curation-ready record using the common envelope and bucket-specific body: explain the reusable meaning, cite exact evidence, distinguish causality from adjacency, preserve known/possible states, evidence gaps and suggested curated targets. When evidence answers an Atlas open question, cite every originating qualified `<record-id>#<question-id>` in the body so active evidence can be detected without creating a new frontmatter field.
5. Flag sensitive artifacts without copying values. Never revise committed evidence; corrections are new staging records and only lifecycle may later alter top-level `status`.
6. Never write curated knowledge or generated artifacts. Run permitted validation unless explicitly deferred, then create the shared exact-path local commit on the selected feature branch.
7. Use the shared plain-language completion summary, then include the branch/commit, new record, source evidence, duplicate-search routes and lifecycle as audit detail.
