# Flows policy

## Purpose
Curated end-to-end flow knowledge.
## Trust level
Only `status: curated` is authoritative; proposed pages require human review.
## When to use this area
End-to-end operational/data paths crossing meaningful steps or components.
## When not to use it
Do not store raw evidence, local implementation trivia, secrets or unsupported claims.
## Granularity rule
One page per meaningful end-to-end path.
## Storage/filename convention
Descriptive kebab-case filenames; IDs remain stable across moves.
## Required frontmatter/type-specific fields
Use `_template.md` and `type: atlas.flow`.
## Relationship guidance
Use approved relationships; `atlas.participates-in` and flow dependencies feed generated maps.
## Evidence expectations
Trace claims to evidence.
## `not covered` rule
Use exactly `*Not covered — no evidence in current staging material.*` when evidence is absent.
## Agent curation instructions
Read README, template and index first; never self-approve.
## Reviewer checklist
Check evidence, boundary, relationships, uncertainty, routing and sensitive data.
## Index maintenance rule
Index all non-archived pages.
## Security/sensitivity reminder
Do not introduce sensitive data.
